# The Agency（agency-agents）用户使用文档

本文档面向**使用者**：说明本项目是什么、如何安装到常用 AI 编程工具，以及如何挑选与激活智能体。更偏贡献与实现的说明见 [开发文档](./开发文档.md)。

---

## 1. 本项目是什么

**The Agency** 是一套以 Markdown 文件形式维护的**专业化 AI 智能体（Agent）人格与工作流**集合。每个智能体通常包含：

- 身份、沟通风格与领域立场  
- 核心使命与可交付成果  
- 必须遵守的领域规则  
- 技术示例（代码、模板、检查清单等）  
- 分步工作流程与成功指标  

你可以把它理解为：**可拷贝、可改编的「专家人设 + 作业说明书」**，供 Claude Code、Cursor、Copilot 等工具在对话中按角色行事。

**许可证**：MIT，可自由用于个人或商业场景（具体以仓库根目录 `LICENSE` 为准）。

---

## 2. 使用前准备

- **克隆或下载**本仓库到本地。  
- **无需** Node/Python 等运行时即可使用源智能体 Markdown；**多工具安装脚本**需要 **Bash**（macOS/Linux 终端，或 Windows 下的 Git Bash / WSL）。  
- 根据你使用的工具，准备好对应产品账号与本地配置目录权限（例如 `~/.claude`、`~/.cursor` 等）。

---

## 3. 三种常见用法

### 3.1 与 Claude Code 配合（直接复制源文件）

将仓库中的智能体复制到 Claude Code 的智能体目录（路径以官方文档为准，常见为 `~/.claude/agents/`）：

```bash
cp -r /path/to/agency-agents/* ~/.claude/agents/
```

在会话中用自然语言引用智能体，例如：「请以 Frontend Developer 的视角审查这个组件。」

### 3.2 仅作参考（不安装）

直接在仓库中打开对应 `*.md` 文件，将其中段落复制到你的提示词、内部文档或自有 Agent 配置中，并按项目需要删减或本地化。

### 3.3 多工具一键转换与安装（推荐想同时用 Cursor、Aider 等时）

在仓库根目录执行：

```bash
./scripts/convert.sh
./scripts/install.sh
```

- `convert.sh`：根据源 Markdown **生成**各工具所需的格式到 `integrations/<工具名>/`（不写用户家目录）。  
- `install.sh`：将已生成的文件**复制**到本机对应工具的配置位置；支持交互式勾选与非交互模式。

**仅安装某一工具示例：**

```bash
./scripts/install.sh --tool cursor
./scripts/install.sh --tool claude-code
```

**加速（多核并行，日志顺序可能交错）：**

```bash
./scripts/convert.sh --parallel
./scripts/install.sh --no-interactive --parallel
```

**项目级工具**（OpenCode、Cursor、Aider、Windsurf 等）：请在**目标项目根目录**运行 `install.sh`，以便规则写入该项目的 `.cursor/rules`、`.opencode` 等路径。详见各工具说明：[integrations/README.md](../integrations/README.md)。

**Gemini CLI**：新克隆仓库后通常需要先单独转换再安装：

```bash
./scripts/convert.sh --tool gemini-cli
./scripts/install.sh --tool gemini-cli
```

修改或新增智能体后，应重新执行 `convert.sh`（可全量或按 `--tool` 指定），再按需 `install.sh`。

## 4. 仓库里智能体怎么分类

源文件按**业务条线目录**存放（与 README 中「分部」一致），例如：

| 目录 | 说明 |
|------|------|
| `engineering/` | 工程与基础设施（前端、后端、SRE、安全等） |
| `design/` | 设计与体验 |
| `marketing/`、`paid-media/`、`sales/` | 市场、投放、销售 |
| `product/`、`project-management/` | 产品与项目推进 |
| `testing/`、`support/` | 测试与运营支持 |
| `spatial-computing/` | 空间计算 / XR |
| `game-development/` | 游戏开发（含引擎子目录） |
| `academic/` | 学术向叙事与世界观支撑 |
| `specialized/` | 难以归入上述类目的专项角色 |
| `strategy/` | 编排 playbook、runbook、NEXUS 相关策略文档（非单智能体源文件） |

具体名单与表格见根目录 [README.md](../README.md)。

## 5. 如何选用智能体

1. **按任务选**：在 README 的分部表格中按「何时使用」列筛选。  
2. **按文件选**：进入对应目录，打开 `领域-角色名.md`，阅读 frontmatter 中的 `name` / `description`。  
3. **组合使用**：复杂任务可同时在对话中点名多个角色，或使用下文 **NEXUS** 中的现成提示模板做分阶段编排。

**示例工作流与多智能体协作输出**见 [examples/README.md](../examples/README.md)（如 `nexus-spatial-discovery.md` 等）。

## 7. 各工具行为差异（摘要）

| 工具 | 安装结果大致形态 | 使用提示 |
|------|------------------|----------|
| Claude Code / Copilot | 多份 `.md` 智能体文件 | 对话中按名称引用智能体 |
| Cursor | `.mdc` 规则文件 | 可用 `@规则名` 等方式引用（见 [integrations/cursor/README.md](../integrations/cursor/README.md)） |
| Aider | 合并后的 `CONVENTIONS.md` | 在会话中说明要遵循的 Agent 风格 |
| Antigravity / Gemini CLI | 每智能体一份 `SKILL.md` 等 | 按各 README 中的 `@` 或扩展机制调用 |
| OpenCode / Qwen / Kimi / OpenClaw | 各工具自有目录与格式 | 以 [integrations/](../integrations/) 下对应 README 为准 |

完整列表与命令见 [integrations/README.md](../integrations/README.md) 与根目录 README 的 **Multi-Tool Integrations** 章节。

## 8. 常见问题

**Q：安装后对话里模型没有按人设回复？**  
A：请明确说出智能体名称或规则名，并附上任务边界；部分工具需手动 `@` 规则或选择 Agent。若刚改过仓库内 Markdown，需重新 `convert.sh` + `install.sh`。

**Q：只想用其中一个智能体？**  
A：可直接打开对应 `.md` 复制全文或片段到提示词；不必运行安装脚本。

**Q：有没有中文版智能体？**  
A：上游 README 列出了社区维护的中文翻译仓库链接；本仓库主体内容为英文智能体定义。

**Q：想贡献新智能体或改现有内容？**  
A：见 [CONTRIBUTING_zh-CN.md](../CONTRIBUTING_zh-CN.md) 与 [开发文档](./开发文档.md)。
