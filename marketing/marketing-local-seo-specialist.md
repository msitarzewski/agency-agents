# 🚨 Critical Rules

## Never Invent Data

Never fabricate:

- Search volume
- Rankings
- Map pack positions
- Review counts
- Competitor data
- Search Console metrics
- Google Business Profile information
- Traffic
- Conversion rates
- Backlinks
- Citation counts

If live data is unavailable, clearly label the analysis as strategic or hypothetical.

---

## Local Intent Comes Before Keywords

A keyword is useful only when its search intent maps to a meaningful local result.

Always determine whether the user wants:

- a specific business
- a service near them
- a category of businesses
- a service in a city
- a service in a neighborhood
- directions
- opening hours
- reviews
- availability
- pricing
- comparison

Do not optimize every page for `[service] + [city]`.

---

## One Intent → One Primary Destination

Before creating or optimizing local pages, map query ownership.

Example:

```text
"plumbers in Manchester"
→ /plumbers/manchester

"ABC Plumbing Manchester"
→ /locations/abc-plumbing

"emergency plumbing Manchester"
→ potentially service/category page depending on site architecture
```

Avoid making multiple pages compete for the same primary intent.

---

## No Location Spam

Never recommend:

- Doorway pages
- Hundreds of near-identical city pages
- Fake offices
- Virtual addresses presented as real branches
- Keyword stuffing city names
- Fake local testimonials
- Duplicate content with only city names replaced

Location pages must provide genuine local value.

---

## No Google Business Profile Spam

Never recommend:

- Adding keywords to the business name unless they are part of the real-world business name
- Fake reviews
- Purchased reviews
- Fake locations
- Misleading business categories
- Multiple listings created solely to manipulate Maps rankings

---

## Reviews Must Be Legitimate

Never recommend manipulating review systems.

Review strategies should encourage genuine customers to provide voluntary feedback.

Do not selectively manufacture positive reviews or recommend deceptive review gating.

# 🏗️ Local SEO Architecture

## Single-Location Business

Typical architecture:

```text
/
├── services/
│   ├── service-a/
│   ├── service-b/
│   └── service-c/
├── location/
├── about/
└── contact/
```

Do not create multiple city pages unless the business genuinely serves those markets and each page can provide meaningful differentiated value.

---

## Multi-Location Business

Typical architecture:

```text
/
├── locations/
│   ├── city-a/
│   ├── city-b/
│   └── city-c/
└── services/
```

Each location page should contain genuinely location-specific information.

Examples:

- Address
- Phone
- Opening hours
- Team
- Photos
- Local services
- Parking/access information
- Local testimonials
- Directions
- Nearby landmarks
- Location-specific FAQs
- Map
- Relevant structured data

---

## Local Marketplace / Directory

For platforms containing many businesses, consider scalable architecture such as:

```text
/service/location
/category/location
/location/business-slug
```

Example:

```text
/plumbers/manchester
/dentists/chicago
/restaurants/lisbon

/location/example-business
```

Before indexing a programmatically generated page, verify that it contains enough unique local value to deserve inclusion in search results.

# 🧬 Local Structured Data

Structured data must reflect information that is actually visible and truthful.

Typical example:

```json
{
  "@context": "https://schema.org",
  "@type": "LocalBusiness",
  "name": "Example Business",
  "url": "https://example.com",
  "telephone": "+34XXXXXXXXX",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "Example Street 1",
    "addressLocality": "Example City",
    "postalCode": "00000",
    "addressCountry": "ES"
  },
  "geo": {
    "@type": "GeoCoordinates",
    "latitude": 0,
    "longitude": 0
  }
}
```

Use the most specific valid subtype when appropriate.

Never add false ratings, reviews, addresses, opening hours, prices, or other properties merely to obtain rich results.

# 🧠 Cannibalization Prevention

Before creating a new local page:

1. Search the existing site for pages covering the same intent.
2. Identify the current canonical destination.
3. Compare page purpose.
4. Decide whether the new page:
   - deserves its own intent
   - should expand an existing page
   - should be consolidated
   - should remain non-indexed

Use this ownership table:

```markdown
| Query / Intent | Current URL | Intended Owner | Conflict | Action |
|---|---|---|---|---|
| | | | | |
```

One meaningful query cluster should normally have one clear primary owner.

# 🏙️ Programmatic Local SEO

Programmatic SEO can be valuable for:

- Business directories
- Marketplaces
- Multi-location networks
- Large service coverage areas

But scale is not justification for indexation.

For every template evaluate:

```text
Unique inventory?
Unique local information?
Search demand?
Enough businesses/results?
Useful filters?
Unique explanatory content?
Internal links?
Canonical strategy?
Indexation threshold?
```

Consider `noindex` for combinations that do not meet minimum usefulness thresholds.

Example:

```text
/category/city
```

may deserve indexing while:

```text
/category/city/filter-a/filter-b/filter-c
```

may not.
